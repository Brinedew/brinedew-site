# MVP PRD — “Protein Guessr” (daily molecular Tradle for brinedew.bio)

## 0) What this is (and isn’t)

* **Goal:** One daily protein (human, UniProt/ HGNC handle). Players infer the target from a compact **clue card** (function + expression + domains), submit HGNC guesses, get structured feedback, and share a spoiler-free result.
* **Non-goals (MVP):** no accounts, no server, no leaderboards, no live API calls. Everything is static assets that Quartz can ship.

## 1) Users & constraints

* Audience: bio-literate crowd who can type HGNC symbols; mobile + desktop.
* Constraint: **Static site (Quartz 4.5.1)**; you already run “Interactive Apps” as static frontends. We’ll mirror that deployment pattern: one JS bundle + one JSON dataset. ([Brinedew][2])

## 2) Core loop (single screen)

1. Open `/apps/protein-guessr/` → loads **today’s target** from a precomputed index.
2. See **Clue Card v0** (minimal, readable at a glance):

   * **Function chips:** GO-Slim terms (3–5 terms). *(CC BY 4.0; safe to reuse with attribution.)* ([Gene Ontology Resource][3])
   * **Expression mini-bars:** top-3 tissues (TPM tiers) from GTEx or HPA. *(GTEx/HPA allow reuse with attribution; HPA is CC BY-SA.)* ([gtexportal.org][4])
   * **Domain badges:** InterPro names (e.g., “EGF-like”, “Ankyrin repeat”). *(InterPro is free to reuse with citation.)* ([OUP Academic][5])
   * **Binary flags:** Transmembrane? Secreted? (iconic toggles).
3. User types a guess (HGNC symbol autocomplete).
4. On submit: **feedback panel** shows similarity vs target on three axes; next hint unlocks.

   * **GO overlap** (Jaccard) → % bar
   * **Expression correlation** (Pearson on 30-tissue vector, or top-k cosine) → arrow up/down + %
   * **Domain overlap** (set overlap) → chips colored by match
   * Always show **length delta** (binned) and **TM/secreted match** (✓ / ✗)
5. Up to 6 guesses. Reveal target + quick link to its **Brinedew wiki page** (you already have these per protein). ([Brinedew][1])
6. Share text (Unicode boxes ala Wordle, no spoilers).

## 3) Scope (MVP, deliverable)

* **Static data pack** of ~300–800 human proteins (UniProtKB/Swiss-Prot slice to avoid garbage), each with:

  * `uniprot`, `hgnc`, `synonyms[]`, `length`, `tmh`, `secreted`, `domains[]` (InterPro short names), `go_slim[]`, `tissues{}` (normalized), `subcell[]`, `links{uniprot, wiki}`
* **Single-page app** under `/apps/protein-guessr/` with:

  * Autocomplete over `hgnc/synonyms`
  * Scoring/feedback
  * Daily selection logic (date-salt)
  * Zero runtime network calls after initial JSON

**Why not just** pull live APIs? Because static assets sidestep CORS/quotas, keep page loads deterministic, and Claude can regenerate the JSON overnight with your other site jobs. If you want “live later,” the schema already matches UniProt/InterPro/GO/GTEx conventions. ([UniProt][6])

## 4) Data sources & license notes (fact)

* **UniProtKB/Swiss-Prot** for canonical sequence length + reviewed status; API stable and documented. *(License & API docs)* ([UniProt][6])
* **InterPro** for domain/family labels (compact, low-entropy clues), reuse permitted with citation. ([OUP Academic][5])
* **Gene Ontology (GO-Slim)** for high-level function chips; **CC BY 4.0** attribution needed. ([Gene Ontology Resource][3])
* **GTEx** (or **Human Protein Atlas**) for tissue expression vectors; both allow reuse with attribution; HPA is **CC BY-SA** for copyrightable parts. Pick one to avoid license mixing. ([gtexportal.org][4])

> Practical call: **Use GTEx for MVP** to dodge CC-BY-SA share-alike contamination site-wide. HPA can be a future toggle if you want their subcell images. ([gtexportal.org][4])

## 6) Daily selection (deterministic, no backend)

* **Input:** `eligible_ids[]` array + `SALT` string baked into `index.json`.
* **Algorithm:** Compute `hash = SHA256(YYYY-MM-DD + SALT)`, cast to int, `idx = hash % eligible_ids.length`, pick that UniProt.
* **Admin override:** `?answer=P46531` for testing.

## 7) Scoring & feedback (simple, legible)

* **GO similarity:** `jaccard = |G_guess ∩ G_target| / |G_guess ∪ G_target|`
* **Expression:** Pearson r (or cosine if you bin to top-10 tissues). Show arrow with numeric r rounded to one decimal.
* **Domains:** `overlap = |D∩|`; paint matched chips green, unmatched gray.
* **Length bin:** show whether guess is in same bin as target: `<400`, `400–800`, `800–1600`, `>1600`.
* **Binary flags:** TM / secreted: ✓ or ✗.

**Reveal pacing:** start with *one* GO chip + one expression bar; each wrong guess adds another chip/bar/domain, in fixed order. This keeps the “Tradle” drip-feed feel with minimal UI.

## 8) Autocomplete & validation

* Accept **HGNC symbol** primary; fuzzy match against `synonyms[]`. If multiple symbols map to a UniProt, prefer reviewed Swiss-Prot record (status: reviewed). *(That field exists in UniProt.)* ([UniProt][7])

## 10) Build scripts (one-shot data bake, run locally)

Have Claude generate a single Node/Python script that:

1. Reads a seed **CSV/JSON you already have** for Thoteins (HGNC/UniProt + persona basics).
2. Queries **UniProt** (batch) for length + reviewed status and **InterPro** accessions → display names. *(Both have stable APIs.)* ([UniProt][6])
3. Imports a **GO-Slim** mapping (download once) and maps each protein’s GO to slim parents. *(GO provides slims + CC BY 4.0.)* ([Gene Ontology Resource][8])
4. Pulls **GTEx** gene TPMs (download matrix; reduce to 30-tissue means), normalize to z-scores per gene, keep top-N tissues. *(Portal docs/license exist; static reuse OK with attribution.)* ([gtexportal.org][9])
5. Emits `data.json` + `index.json` with `salt_hash`.

If you want “no network calls at all,” Claude can scaffold a **tiny cached extractor** that reads local TSV dumps (UniProt/InterPro/GO/GTEx releases) and produces the same `data.json`.

## 11) Acceptance criteria (MVP)

* Loads in <2 s on mobile; no network after first JSON fetch.
* 1 playable puzzle per calendar day (Asia/Ho_Chi_Minh).
* 6-guess cap; each wrong guess unlocks exactly one new hint.
* Autocomplete over ≥300 proteins; synonyms recognized.
* Share text button outputs a 3-line spoiler-free block.

## 12) Success metrics (minimally invasive)

* Local counters only (no tracking scripts): store `{date, guesses, win}` in `localStorage` and render streaks client-side.
* Optional: write a daily JSON to `/apps/protein-guessr/` with the **minimum** aggregate (plays, median guesses) during your static build, if you later add a cron job.

## 13) Risks & mitigations

* **License mixing (HPA CC-BY-SA)**: stick to **GTEx** for MVP to avoid site-wide share-alike; keep HPA behind a feature flag. ([proteinatlas.org][10])
* **Over-narrow clues:** some proteins look identical at GO-Slim level. Mitigation: ensure each target has **at least one distinctive domain badge** (e.g., “homeobox”, “kinase”, “zinc finger C2H2”) or a distinctive expression triad.
* **Ambiguous synonyms:** rely on UniProt reviewed entries and a **symbol → UniProt** canonical map.

### Pseudocode: date picker + scoring

```js
function pickToday(eligibleIds, salt) {
  const d = new Date().toISOString().slice(0,10); // YYYY-MM-DD (local)
  const msg = d + "|" + salt;
  const hash = sha256(msg);          // e.g., from a tiny SHA lib
  const n = parseInt(hash.slice(0,16), 16);
  return eligibleIds[n % eligibleIds.length];
}

function scoreGuess(guess, target) {
  const jaccard = jaccardIndex(new Set(guess.go_slim), new Set(target.go_slim));
  const exprR   = pearson(guess.tissueVec, target.tissueVec); // or cosine
  const domOv   = overlapCount(new Set(guess.domains), new Set(target.domains));
  const lenBin  = binLength(guess.length) === binLength(target.length);
  const tmHit   = guess.tmh === target.tmh;
  const secHit  = guess.secreted === target.secreted;

  return { jaccard, exprR, domOv, lenBin, tmHit, secHit };
}
```
