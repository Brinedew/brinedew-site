## Executive Summary
A static gene database where each human gene is represented by a consistent human portrait, generated from mapped molecular parameters. Think "yearbook for the human genome" - each gene gets a deterministic face that encodes its molecular properties into human characteristics.

## Core Concept
**1 gene = 1 human portrait**
- Molecular properties (mass, expression, function) → Human attributes (height, clothing, pose)
- Deterministic mapping ensures consistency across all viewers
- Editorial magazine cover aesthetic per gene

## Technical Architecture

### Data Pipeline

UniProt IDs → Query APIs → Parameter Extraction → Mapping Rules → Prompt Generation → Image API → Cache & Display

### Phase 1.5: Parameter dimensionality determination

Make a "molecular_dimensions" table for molecular parameters.
1 column per parameter you can fetch from databases
Row 1: parameter name + unit of measure (if any)
Row 2: quantitative or qualitative?

For quantitative:
Row 3: minimum value
Row 4: minimum value gene
Row 5: maximum value
Row 6: maximum value gene

For qualitative:
Row 3: number of bins
Row 4: number of genes with exactly 1 bin listed
Row 5: number of genes with 2+ bins 
Row 6: number of genes with unassigned/0/NA (don't listed under any bin)

In the same file, on the later rows (row 10+) make a "human_dimensions" table for human parameters.
1 column per parameter you can imagine (ask yourself: how would a policeman describe a person when alarming the station?)
Row 1: parameter name + unit of measure (if any)
Row 2: quantitative or qualitative?

For quantitative:
Row 3: minimum value in humans
Row 4: maximum value in humans

For qualitative:
Row 3: number of bins
Row 4: Can humans fall in only 1 bin? Y/N
Row 5: Can humans fall in 2+ bins? Y/N 
Row 6: Can humans fall into none of the bins? Y/N

### Phase 3: Core Scripts

**fetch_gene_data.py** - Aggregates data from multiple sources:
```python
# Queries:
# - UniProt: mass, length, domains, subcellular location
# - STRING-db: interaction partners count
# - Human Protein Atlas: tissue expression
# - gnomAD: variant frequency
# - GO: functional categories
# Outputs to gene_metadata.json
```

**generate_portraits.py** - Creates deterministic prompts and calls OpenAI:
```python
# For each gene:
# 1. Load molecular parameters from gene_metadata.json
# 2. Apply mappings from parameter_mappings.csv
# 3. Fill prompt template
# 4. Call DALL-E 3 API (with fixed seed)
# 5. Save image to /static/gene-portraits/
# 6. Log generation params to generation_log.json
```

**create_pages.py** - Generates Markdown files for Quartz:
```python
# Creates:
# - Individual gene pages with portrait + stats
# - Gallery index page
# - Stats/analytics page
# Uses Quartz frontmatter for tagging/categorization
```

## Data Sources & Mappings

### Priority 1 Mappings (Clear correlations)
- **Molecular weight** → Height (50-500 kDa → 150-190 cm)
- **Conservation score** → Age (0-1 → 20-70 years)
- **Tissue specificity index** → Fashion formality (0-1 → casual-formal)
- **Subcellular location** → Background setting
- **Pathogenicity scores** → Facial expression intensity

### Priority 2 Mappings (Interpretive)
- **GO biological process** → Clothing category (via keyword extraction)
- **Domain count** → Complexity of outfit/accessories
- **Expression variance** → Hair style (uniform vs. wild)
- **Interaction degree** → Social pose (alone vs. group)

### Randomized Elements (for uniqueness)
- Specific facial features (within type)
- Exact pose angles
- Color palette variations (within clothing style)
- Minor accessories

## Resource Requirements
- **Time**: ~10 hours setup, 2 hours generation
- **Cost**: ~$200 for 100 DALL-E 3 images
- **Storage**: ~100MB for images
- **APIs**: UniProt, STRING-db (free tier sufficient)

## Risk Mitigations
- **API rate limits**: Batch with delays, cache everything
- **Prompt failures**: Fallback templates, manual overrides
- **Duplicate appearances**: Accept as feature ("gene twins")
- **Offensive generations**: Pre-screen sensitive genes manually
